# JW PowerCache v0.4.0

This general release fixes cache correctness and scheduled recovery issues found in the September 7 API audit and makes the update discoverable through G7's plugin updater. It includes the previously unpublished beta.2 changes and does not change the supported API routes or the Loading UX.

## Fixes

- Bypass GET/HEAD requests with raw, parsed, or uploaded body input, so body-only board filters cannot fill or read the plain list cache.
- Partition responses by G7's effective user timezone, matching the timezone used to render API dates.
- Capture the current outbox event token before scheduled/CLI replay and clear only that token after recovery. Preserve newer writers and in-progress control-plane resets.
- Recheck the clean barrier token, site/runtime epoch, and generations after reading cached responses, including both lock paths, and before storing origin responses.
- Move response keys to policy `response-api-v4`, preventing reuse of responses stored under the old policy.

## Updating

- Version: `0.4.0`; minimum G7 version remains `7.0.9`.
- Use G7's plugin updater to install the published update. No new database migration or setting is required.
- Existing cache mode and Loading UX settings remain configured as before.
- The next scheduled reconciliation also clears an old outbox event barrier whose database work was already completed. The scheduler must be running.
- GitHub's `/releases/latest` endpoint, used by G7, excludes draft and prerelease entries. A branch push alone does not make a version visible to G7's update checker.
- The beta suffix has been removed. The stock G7 commit-to-hook failure window and documented maintenance requirements still apply; this is not a new atomic-consistency guarantee or the 1.0 milestone.
